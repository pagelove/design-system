# Instructions for design-system consumers and contributors

- Read designs/catalog.json first. Select the requested design ID; otherwise use its configured defaultDesign/defaultMode. For an explicitly selected design with no mode, use that design's defaultMode. Read designs/<id>/DESIGN.md, docs/designs.md and docs/document-first.md. Root DESIGN.md represents only the configured default. Never invent an unavailable mode or mix another design's visual values into the selected design.
- Prefer semantic HTML for document-based domain information and DOM-backed editing. Required interchange, external authorities and specialized runtimes are justified exceptions. Token JSON does not change this app-data preference.
- Edit shared tokens/foundations.json and tokens/semantic.json, designs/catalog.json, and designs/<id>/design.json. Regenerate dependent formats with `npm run build`; do not independently edit outputs. tokens/profiles.json is historical reference material, not the runtime design source.
- Use shared semantic roles in components and select the full design with data-design plus a supported data-theme on the HTML element. Designs supply complete colors, typography, shapes and spacing. Read that design's exports when integrating another tool.
- Keep visible labels, native control semantics, keyboard operation, focus and useful status text. Use neutral panel borders. Do not add decorative northeast arrow icons or colored card rails.
- Retain provenance and license notices. Keep operational records, credentials, personal paths and organization-private material out of the public repository. Repository links must be within the pagelove organization.
- Record a scoped plan and meaningful change batches in audit/CHANGELOG.md, with UTC time, actor, rationale, affected files and verification. Preserve previous records.
- Run `npm ci` for the pinned development validators, then `npm run build`, `npm run check` and `npm run check:external`. UI changes also require `npm run test:browser` in the documented browser environment; review visual diffs before updating baselines. For UI changes, separately inspect browser tasks and responsive/reduced-motion states. State tool or environment limits; static checks do not prove browser behavior.
- Framework adapters are examples, not packaged component libraries. Do not claim a Figma/Stitch/native import passed without actually testing it in that tool.
