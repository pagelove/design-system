# Content and recovery

Use the same voice across designs: direct, respectful and specific. Visual character changes; the meaning of an action does not. Use sentence case. Name actions with a verb and object. Keep essential instructions visible; a tooltip is supplementary.

| Situation | Pattern | Example |
| --- | --- | --- |
| Empty collection | Explain what belongs here and offer the first action | No projects yet. Create a project. |
| No search results | Repeat the scope and offer recovery | No projects match this search. Clear search. |
| Invalid input | Identify the field and correction; preserve the input | Enter an email address in the format name@example.com. |
| Network failure | State what failed, what was retained and a safe next step | Your changes could not be saved. Your draft is still here. Try again. |
| Pending action | Keep the action recognizable; avoid invented duration | Saving description… |
| Destructive action | Name the affected item and consequence; prefer the safe initial focus | Delete this draft? This cannot be undone. |
| Permission failure | Distinguish lack of access from absent data | You do not have access to this project. Contact its owner. |
| Local demonstration | State the persistence boundary | Saved in this preview. Reloading resets it. |

Do not announce routine changes repeatedly. Use a polite status region for asynchronous outcomes; reserve alerts for urgent errors. Include units and time zones where ambiguity affects a decision. Use locale formatting and plural rules rather than concatenated English strings. Avoid truncating the only available name for a resource.

## Charts and new compositions

UI success/error colors are not a categorical chart palette. For a chart-specific extension, define categorical and sequential roles per supported mode, labels/patterns as alternatives to color, a text/table equivalent and explicit unknown/missing-data states. Validate the chart in its actual context before adding those roles to the canonical source.

The shared Studio fixture intentionally isolates theme differences. Add an editorial reader, dense table or mobile workflow only with a concrete task and acceptance evidence. Do not invent native adapters or additional color schemes merely to increase format counts.
